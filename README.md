# lab-project-board · 实验室项目展示板

## 项目简介

这是我用来练手的一个小网页:把实验室里正在做的项目列出来,每个项目一张卡片,显示名称、简介、成员、技术栈和 GitHub 地址。可以自己新增项目、删除项目,也可以按名称搜索。

数据存在浏览器的 `localStorage` 里,没有后端、没有数据库,也不需要注册登录——纯粹是前端练手用的。

> 说白了,这是我学 Vue 3 时做的一个练习,不是要上线的产品。代码里尽量写了中文注释,方便自己以后回来看。

## 已实现功能

- **项目列表**:每张卡片显示项目名称、状态、简介、技术栈标签、成员、GitHub 链接
- **项目 Logo**:每张卡片左上角有一个渐变小图标,图标按项目名称/简介/技术栈里的关键词自动匹配(垃圾分类→叶子、图书→书、预约→日历),配色按项目 id 轮流取,所以每个项目的 logo 都不一样,新增项目也不用手动设置
- **深色模式**:右上角可以在浅色/深色之间自由切换,选择会被记住;没有手动选过时跟随系统偏好
- **新增项目**:点「新增项目」展开表单,填写后加入列表(名称必填,其他可以留空)
- **编辑项目**:点卡片上的「编辑」,表单会自动填上这条项目原来的内容,改完点「保存修改」;正在编辑的卡片会高亮,免得改错条目
- **删除项目**:点卡片上的「删除」,会先弹确认框,确认后才真的删掉
- **按名称搜索**:输入框里边打字边过滤,不区分大小写(搜 `vue` 也能匹配到 `Vue 3`)
- **项目排序**:搜索框右边可以选择排序规则(添加顺序 / 名称 / 状态 / 成员数量 / 技术栈数量),旁边按钮一键切换升序降序;按中文拼音排,选择会被记住。排序和搜索可以叠加使用
- **状态标签**:进行中 / 已完成 / 暂停,三种状态用不同颜色区分
- **本地保存**:数据存在 `localStorage`,刷新页面不会丢
- **示例数据**:第一次打开时显示 3 条示例项目,方便直接看到效果
- **自适应布局**:屏幕宽时卡片自动排成两列,窄时变成一列

## 使用技术

| 技术 | 版本 | 说明 |
| --- | --- | --- |
| Vue 3 | 3.5.43 | 用 `<script setup>` 写法,Composition API |
| Vite | 8.3.4 | 开发服务器 + 打包工具 |
| @vitejs/plugin-vue | 6.0.9 | 让 Vite 能编译 `.vue` 文件 |
| 原生 CSS | — | 写在组件的 `<style scoped>` 里,没有用 UI 框架 |
| localStorage | — | 浏览器自带的本地存储,代替数据库 |

没有引入 Vue Router、Pinia 这类东西——目前只有一个页面,用不上。

## 如何安装

需要先装 [Node.js](https://nodejs.org/)(建议 20 以上,我开发时用的是 v22.22.2)。

```bash
# 1. 把项目克隆到本地
git clone <仓库地址>
cd lab-project-board

# 2. 安装依赖
npm install
```

`npm install` 会根据 `package.json` 把 Vue、Vite 这些依赖下载到 `node_modules` 目录。这个目录不用提交到 Git,已经在 `.gitignore` 里排除了。

## 如何运行

```bash
# 启动开发服务器(改代码会自动刷新)
npm run dev
```

运行后终端会打印一个本地地址,一般是 <http://localhost:5173>,在浏览器里打开就能看到页面。

其他两个命令平时不太用,顺便记一下:

```bash
# 打包成能部署的静态文件,输出到 dist/
npm run build

# 本地预览打包后的结果
npm run preview
```

## 我通过这个项目学习到了什么

写这个项目的过程中,下面这些是真正自己动手之后才搞明白的:

- **组件怎么拆**:`App.vue` 管数据,`ProjectCard.vue` 只负责显示,`ProjectForm.vue` 只负责收集输入。一开始我什么都往 `App.vue` 里塞,后来才拆开,拆完确实清爽很多。
- **数据怎么在组件之间走**:父组件用 `props` 把数据传下去(卡片拿不到数据就没法显示),子组件用 `emit` 把事件抛上来(卡片不知道"删除"该怎么做,它只管喊一声)。
- **`v-model` 双向绑定**:输入框和变量绑在一起,用户打字变量就变,变量变输入框也跟着变。搜索框能"边打字边过滤"就是靠它。
- **一个组件可以干两件事**:新增和编辑用的是同一个 `ProjectForm`。传 `project` 进去就是编辑,不传就是新增——比复制一份几乎一样的表单省事得多,以后改字段也只用改一处。
- **`computed` 和 `watch` 的区别**:`computed` 是"算出来的数据",搜索过滤用它;`watch` 是"数据变了就做点别的",自动存 localStorage 用它。
- **排序要"先筛后排"**:一开始想把过滤和排序揉在一个 `computed` 里,写出来特别绕。后来拆成"先 filter 缩小范围,再 sort 调整顺序"两步,一下子就看懂了——而且搜索和排序能自动叠加,不用写两遍。
- **中文排序不能直接比较**:`'张' > '赵'` 是按字符编码比出来的结果,不符合直觉。要用 `localeCompare(名字, 'zh-Hans-CN')` 才会按拼音排。
- **`sort` 是稳定排序**:比较结果为 0 的两项不会被打乱次序。所以"按状态排"时,同一状态内部仍保持添加顺序,看起来很自然。
- **排序不能改到原数组**:如果直接 `projects.value.sort()`,会把源头数据也改掉,连带写进 localStorage,刷新后顺序就真变了。要先复制一份(`[...projects.value]`)再排。
- **`v-for` 一定要写 `key`**:一开始漏了,列表更新时出现过奇怪的问题。
- **`scoped` 样式**:写在组件里的样式不会污染别的组件,不用再费劲想类名。
- **localStorage 只能存字符串**:存的时候要 `JSON.stringify`,读的时候要 `JSON.parse`;而且读的时候一定要 `try/catch`,不然存坏了整个页面会白屏。
- **要考虑到老数据**:我中途把状态从"规划中"改成了"暂停",已经存过的数据不会自动更新,所以加了一小段兼容代码把旧值换掉。
- **CSS Grid 挺好用**:`repeat(auto-fill, minmax(320px, 1fr))` 一行就让卡片自己适应屏幕宽度。
- **`v-html` 插进来的元素拿不到 `scoped` 样式**:卡片的小图标是用 `v-html` 动态插进去的 SVG,尺寸怎么写都不生效。后来才明白 `scoped` 是靠给元素加一个 `data-v` 属性实现的,而 `v-html` 生成的元素身上没有这个属性,必须写成 `:deep(svg)` 才能选中。
- **CSS 变量很适合做主题**:把颜色抽成变量之后,深色模式就只是"换一套变量值",组件里一行判断都不用写。
- **用 Git 管版本**:这是第一次完整走 `git init` → `git add` → `git commit` 的流程,也搞清楚了"工作区、暂存区、提交"这三步到底是在干什么。
